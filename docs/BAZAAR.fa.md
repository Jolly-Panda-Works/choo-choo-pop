# نسخه‌ی کافه‌بازار (هو هو چی چی)

بازی یک نسخه دارد و بازیکن زبان را در تنظیمات عوض می‌کند. بیلد بازار (`VITE_STORE=bazaar` و `-PEDITION=fa`) با زبان فارسی شروع می‌شود، خدمات بازار را دارد و شناسه‌ی بسته‌اش `com.jollypanda.choochoopop.fa` است. ساختار کار مثل Mini Sumo است: روی شاخه‌ی `bazaar` هر push نسخه را می‌سازد (**Actions ← Bazaar**) و تا وقتی نسخه‌ی پایدار نداریم، نسخه فقط به‌صورت پیش‌نویس آلفا به پیشخان می‌رود و به دست عموم نمی‌رسد.

## چه چیزهایی در بازی هست

| قابلیت | جای آن در بازی | کتابخانه |
|---|---|---|
| خرید سکه و حذف تبلیغات | فروشگاه سکه | Poolakey 2.2.0 |
| بازیابی خرید و تکمیل خرید نیمه‌کاره | تنظیمات، و خودکار هنگام شروع | Poolakey |
| ورود با بازار و ذخیره‌ی پیشرفت | تنظیمات؛ هنگام شروع خودکار | CafeBazaarAuth 1.1.0 |
| بررسی وضع ورود به برنامه‌ی بازار | پیش از ورود | ILoginCheckService |
| بررسی نسخه‌ی جدید و پنجره‌ی به‌روزرسانی | هنگام شروع | bazaarUpdater 1.2.0 |
| به‌روزرسانی خودکار | تنظیمات (اگر خاموش باشد) | bazaarUpdater |
| نظر و امتیاز، بازی‌های دیگر | تنظیمات | اینتنت بازار |
| رهانش خودکار | GitHub Actions | API پیشخان |
| خرید اعتباری اسنپ‌پی | خودکار در پنجره‌ی پرداخت بازار، بدون کد | بازار |

### چیزهایی که عمداً اضافه نشد

این بازی سرور ندارد و این موارد بدون سرور امن نیستند، چون کلیدشان نباید داخل APK باشد:

- **بررسی خرید با API توسعه‌دهندگان** (وضعیت خرید، مصرف، عودت): خرید فعلاً با کلید RSA روی گوشی تأیید می‌شود. برای یک بازی آفلاین کودکان کافی است، ولی جلوی تقلب حرفه‌ای را کامل نمی‌گیرد.
- **تخفیف پویا**: توکن JWT آن باید روی سرور امضا شود.
- **اشتراک**: بازی محصول اشتراکی ندارد.

## قدم به قدم

### ۱. ساخت برنامه در پیشخان

۱. به [پیشخان توسعه‌دهندگان](https://pishkhan.cafebazaar.ir) بروید و اگر حساب توسعه‌دهنده ندارید، بسازید.
۲. برنامه‌ی جدید بسازید. شناسه‌ی بسته دقیقاً باید `com.jollypanda.choochoopop.fa` باشد. پیشخان این شناسه را از روی اولین APK می‌خواند، پس ممکن است لازم باشد قدم ۳ را قبل از این کار انجام دهید و APK امضاشده را از GitHub Release بردارید.
۳. اطلاعات صفحه‌ی برنامه را پر کنید: نام، توضیحات، آیکون، تصاویر و رده‌ی سنی (بازی کودکانه است).

### ۲. محصولات درون‌برنامه‌ای

پیشخان ← برنامه ← پرداخت درون‌برنامه‌ای. این محصولات را با همین شناسه‌ها بسازید:

| شناسه | محتوا | نوع |
|---|---|---|
| `coins_small` | ۲۰۰ سکه | مصرف‌شدنی |
| `coins_medium` | ۷۰۰ سکه | مصرف‌شدنی |
| `coins_large` | ۱٬۶۰۰ سکه | مصرف‌شدنی |
| `coins_giant` | ۴٬۰۰۰ سکه | مصرف‌شدنی |
| `remove_ads` | حذف تبلیغات | غیرمصرفی |

قیمت‌ها را در پیشخان تعیین کنید؛ بازی قیمت را از خود بازار می‌خواند.

### ۳. کلید امضا (keystore)

**این کلید را یک بار بسازید و گم نکنید.** به‌روزرسانی برنامه فقط با همان کلید ممکن است. اگر گم شود، باید برنامه را از نو منتشر کنید.

```bash
keytool -genkeypair -v -keystore choo-choo-pop.keystore -alias choochoopop -keyalg RSA -keysize 2048 -validity 10000
```

فایل را کنار بقیه‌ی کلیدها در `F:\Jolly Panda Studio\- KEY` نگه دارید و در مخزن نگذارید. برای GitHub آن را base64 کنید:

```bash
base64 -w 0 choo-choo-pop.keystore > keystore.base64.txt
```

بعد از برداشتن مقدار، فایل `keystore.base64.txt` را پاک کنید.

### ۴. تنظیمات GitHub

مخزن ← Settings ← Secrets and variables ← Actions.

**Secrets:**

| نام | مقدار |
|---|---|
| `KEYSTORE_BASE64` | محتوای `keystore.base64.txt` |
| `KEYSTORE_PASSWORD` | رمز keystore |
| `KEY_ALIAS` | `choochoopop` |
| `KEY_PASSWORD` | رمز کلید |
| `BAZAAR_PISHKHAN_TOKEN` | قدم ۵ |

**Variables:**

| نام | مقدار | لازم است؟ |
|---|---|---|
| `BAZAAR_RSA_KEY` | پیشخان ← برنامه ← پرداخت درون‌برنامه‌ای ← کلید RSA | برای خرید، بله |
| `BAZAAR_DEVELOPER_ID` | شناسه‌ی توسعه‌دهنده در پیشخان | برای دکمه‌ی بازی‌های دیگر |
| `BAZAAR_CHANNEL` | پیش‌فرض `alpha`؛ برای انتشار عمومی `public` | نه |
| `BAZAAR_AUTO_PUBLISH` | پیش‌فرض `false`؛ با `true` بعد از تأیید بازار خودکار منتشر می‌شود | نه |

کلید RSA عمومی است و قرار گرفتنش در APK مشکلی ندارد. بدون آن بیلد موفق است، ولی فروشگاه نسخه‌ی بازار چیزی نمی‌فروشد.

### ۵. توکن API پیشخان (رهانش خودکار)

۱. پیشخان ← برنامه ← **API پیشخان بازار** ← «دریافت توکن جدید».
۲. توکن را در secret `BAZAAR_PISHKHAN_TOKEN` بگذارید.

این توکن رمز است. آن را در کد، فایل `.env` قابل commit یا چت نگذارید.

### ۶. گروه آلفا

پیشخان ← رهانش‌ها ← گروه‌های رهانش ← گروه جدید. شماره‌ی آزمایش‌کننده‌ها را اضافه کنید (تا ۱۰۰ شماره).

### ۷. اولین بیلد

روی شاخه‌ی `bazaar`، فایل `bazaar-release-notes.json` را با نسخه‌ی `package.json` و متن فارسی و انگلیسی پر کنید، بعد commit و push کنید.

بعد از بیلد:

۱. فایل‌ها در GitHub Release با تگ `bazaar-vX.Y.Z` هستند.
۲. اگر توکن گذاشته باشید، APK به‌صورت پیش‌نویس در پیشخان است.
۳. پیشخان ← رهانش‌ها ← مدیریت رهانش‌ها: گروه انتشار را «آلفا» و گروه خود را انتخاب کنید و درخواست بررسی بدهید.

### ۸. آزمایش روی گوشی

برنامه را از طریق لینک گروه آلفا از خود بازار نصب کنید، نه با فایل APK؛ بعضی قابلیت‌های بازار فقط برای نسخه‌ای که از بازار آمده کار می‌کنند.

- [ ] خرید هر بسته‌ی سکه و رسیدن سکه
- [ ] خرید دوباره‌ی همان بسته
- [ ] خرید `remove_ads`، پاک کردن داده‌ی برنامه و «بازیابی خریدها»
- [ ] ورود با بازار، نصب دوباره، و برگشتن پیشرفت
- [ ] انتشار نسخه‌ی بالاتر در آلفا و دیدن پنجره‌ی به‌روزرسانی
- [ ] دکمه‌ی نظر و امتیاز

### ۹. انتشار عمومی (وقتی نسخه‌ی پایدار آماده شد)

متغیر `BAZAAR_CHANNEL` را `public` کنید، یا در Actions ← Bazaar ← Run workflow کانال `public` را انتخاب کنید. برای انتشار خودکار بعد از تأیید بازار، `BAZAAR_AUTO_PUBLISH` را `true` کنید.

## کارهای روزمره

تغییرات را روی `main` بدهید و برای نسخه‌ی جدید بازار:

```bash
git checkout bazaar
git merge main
```

بعد `bazaar-release-notes.json` را برای نسخه‌ی جدید پر کنید:

```bash
git commit -am "chore(bazaar): release notes"
git push
git checkout main
```

- بدون یادداشت نسخه، بیلد بازار متوقف می‌شود.
- `version` در این فایل باید دقیقاً نسخه‌ی `package.json` باشد و هر متن حداکثر ۱۰۰۰ نویسه است.
- بعد از ارسال موفق به بازار، GitHub فایل را خالی می‌کند؛ پیش از کار بعدی `git pull` بزنید.
- این فایل را فقط روی `bazaar` ویرایش کنید.
- `versionCode` از شماره‌ی نسخه ساخته می‌شود (`1.2.0` می‌شود `1002000`)، پس هر انتشار باید نسخه‌ی بالاتری داشته باشد.
