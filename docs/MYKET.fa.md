# نسخه‌ی مایکت (Choo Choo Pop)

نسخه‌ی مایکت کنار نسخه‌ی بازار روی شاخه‌ی `Iranian-store` ساخته می‌شود. این شاخه همان `main` به‌اضافه‌ی تنظیمات دو فروشگاه است: برای هر بیلد، `main` در آن مرج می‌شود و **هیچ‌وقت برعکس**. هر push روی آن هر دو نسخه را می‌سازد (**Actions ← Iranian stores**). راهنمای بازار در [BAZAAR.fa.md](BAZAAR.fa.md) است.

شناسه‌ی بسته و شماره‌ی نسخه در هر دو فروشگاه یکی است و کد مایکت در این جاها است: `src/services/myket.js`، `src/services/platform.myket.jsx`، `android/app/src/myket` و `scripts/myket-release.mjs`.

## چه چیزهایی در بازی هست

| قابلیت | جای آن در بازی | ابزار |
|---|---|---|
| خرید سکه و حذف تبلیغات | فروشگاه سکه | `ir.myket:billing:2.2` |
| بازیابی خرید و تکمیل خرید نیمه‌کاره | خودکار هنگام شروع | `ir.myket:billing` |
| نظر و امتیاز | تنظیمات | اینتنت مایکت |
| بازی‌های دیگر | پنجره‌ی «درباره» | اینتنت مایکت |
| انتشار خودکار | GitHub Actions | API انتشار مایکت |

### تفاوت با نسخه‌ی بازار

ورود با حساب، ذخیره‌ی ابری پیشرفت و به‌روزرسانی درون‌برنامه‌ای فقط در نسخه‌ی بازار هستند، چون مستندات مایکت سرویسی برای آن‌ها معرفی نکرده است. کتابخانه‌ی پرداخت مایکت کتابخانه‌ی شناسه‌ی تبلیغاتی را هم همراه خود می‌آورد؛ چون این بازی برای کودکان است، مجوز `AD_ID` در `android/app/src/myket/AndroidManifest.xml` حذف شده است.

خرید فقط روی گوشی با کلید عمومی تأیید می‌شود، چون بازی سرور ندارد و توکن API مایکت نباید داخل APK باشد.

## قدم به قدم

### ۱. ساخت برنامه در پنل

۱. به [پنل توسعه‌دهندگان مایکت](https://developer.myket.ir) بروید.
۲. برنامه را با شناسه‌ی بسته‌ی `com.jollypanda.choochoopop` ثبت کنید. می‌توانید APK بدهید یا فقط نام بسته را رزرو کنید. APK امضاشده بعد از اولین بیلد در GitHub Release با تگ `myket-vX.Y.Z` است.
۳. اطلاعات صفحه‌ی برنامه را پر کنید: نام، توضیحات، آیکون، تصاویر و رده‌ی سنی.

### ۲. محصولات درون‌برنامه‌ای

این محصولات را با همین شناسه‌ها بسازید:

| شناسه | محتوا | نوع |
|---|---|---|
| `coins_small` | ۲۰۰ سکه | مصرف‌شدنی |
| `coins_medium` | ۷۰۰ سکه | مصرف‌شدنی |
| `coins_large` | ۱٬۶۰۰ سکه | مصرف‌شدنی |
| `coins_giant` | ۴٬۰۰۰ سکه | مصرف‌شدنی |
| `remove_ads` | حذف تبلیغات | غیرمصرفی |

قیمت‌ها را در پنل تعیین کنید؛ بازی قیمت را از خود مایکت می‌خواند.

### ۳. تنظیمات GitHub

مخزن ← Settings ← Secrets and variables ← Actions. کلید امضا همان کلید نسخه‌ی بازار است.

| نوع | نام | مقدار | لازم است؟ |
|---|---|---|---|
| Variable | `MYKET_PUBLIC_KEY` | پنل ← برنامه ← کلید عمومی پرداخت | برای خرید و ارسال به مایکت، بله |
| Secret | `MYKET_ACCESS_TOKEN` | توکن API از پنل توسعه‌دهندگان | برای ارسال خودکار |
| Variable | `MYKET_AUTO_PUBLISH` | پیش‌فرض `false`؛ با `true` بعد از تأیید مایکت خودکار منتشر می‌شود | نه |

توکن رمز است. آن را در کد، فایل `.env` قابل commit یا چت نگذارید. کلید عمومی رمز نیست.

تا وقتی توکن تنظیم نشده باشد، بیلد و GitHub Release مایکت انجام می‌شود ولی چیزی به مایکت نمی‌رود. اگر توکن باشد و `MYKET_PUBLIC_KEY` نباشد، مرحله‌ی ارسال با خطا متوقف می‌شود تا نسخه‌ی بدون خرید منتشر نشود.

### ۴. آزمایش روی گوشی

آخرین نسخه‌ی مایکت را نصب کنید و این موارد را بررسی کنید:

- [ ] خرید هر بسته‌ی سکه و رسیدن سکه
- [ ] خرید دوباره‌ی همان بسته
- [ ] خرید `remove_ads`، پاک کردن داده‌ی برنامه و «بازیابی خریدها»
- [ ] لغو خرید در صفحه‌ی پرداخت
- [ ] دکمه‌ی نظر و امتیاز و بازی‌های دیگر

## کارهای روزمره

کار روزمره با نسخه‌ی بازار یکی است و یادداشت نسخه هم مشترک است؛ بخش «کارهای روزمره» در [BAZAAR.fa.md](BAZAAR.fa.md) را ببینید.

- بدون یادداشتی که `version` آن با نسخه‌ی بیلد یکی باشد، چیزی به مایکت نمی‌رود.
- یادداشت نسخه برای هر دو فروشگاه یکی است، پس در آن از قابلیتی که فقط در یک فروشگاه هست ننویسید.

- اسکریپت قبل از ارسال نگاه می‌کند که این `versionCode` در مایکت در حال بررسی یا تأییدشده نباشد.
- بسته‌ی ناتمام قبلی (`JustCreated`) پیش از ارسال حذف می‌شود، حتی اگر آن را دستی در پنل ساخته باشید.
- اگر یک فروشگاه خطا بدهد، فروشگاه دیگر کار خودش را ادامه می‌دهد.
- یادداشت نسخه فقط وقتی خالی می‌شود که هر دو فروشگاه تنظیم شده باشند و هر دو بیلد موفق باشد.
